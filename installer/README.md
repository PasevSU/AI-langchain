# pasevsu-installer-agent

Инсталационен агент за това хранилище. Изпълнява **реалната миграция при първо
стартиране** и публикува резултата: избира само агентите с ясно заявена промяна,
прави проверен бекъп, прилага промените в репото, пуска тестовете и публикува
ъпдейт.

Пакетът е **само стандартна библиотека** — не изисква `pip install`, `uv sync`
или виртуална среда, защото работата му е да *извърши* инсталацията.

## Бърз старт

```bash
python -m pasevsu_installer status                  # само четене: какво е станало
python -m pasevsu_installer install --dry-run       # план, без промени по диска
python -m pasevsu_installer install                 # истинската миграция
python -m pasevsu_installer install --agents installer-bootstrap,installer-docs
python -m pasevsu_installer install --no-publish    # без комит/таг
python -m pasevsu_installer reset --force           # изчисти състоянието
pwsh -File installer/scripts/verify.ps1             # едната проверка преди публикуване
```

`install` е verb по подразбиране: `python -m pasevsu_installer` прави същото.

## Флагове

| Флаг | Значение |
| --- | --- |
| `--root <път>` | корен на хранилището (по подразбиране текущата папка) |
| `--config <път>` | конфигурация (по подразбиране `installer/installer.config.json`) |
| `--agents a,b` | ограничи изпълнението до изброените агенти |
| `--dry-run` | предсказва всяка операция, нищо не се записва |
| `--no-tests` | пропусни тестовите пакети (не се препоръчва) |
| `--no-publish` | пропусни комит/таг/пуш |
| `--force` | вдигни проверката „вече е завършил“ и гейта за празен пуск (не преизпълнява приложени задачи) |
| `--status` | съкращение за verb `status` |
| `--reset` | съкращение за verb `reset` (изисква `--force`) |

## Кодове за изход

| Код | Значение |
| --- | --- |
| `0` | успех (включително „няма заявени промени“) |
| `1` | неуспешна стъпка: прилагане, тестове или публикуване |
| `2` | невалидна конфигурация или липсващ аргумент |
| `3` | друг процес държи ключалката (`.installer/lock.json`) |

## Порядък на изпълнение

```mermaid
flowchart LR
    A[selection] --> B[backup]
    B --> C[apply]
    C --> D[tests]
    D --> E[publish]
```

1. **selection** — зарежда `installer/agents/*.json`, изхвърля агентите без
   `status: active` и задачите без `declared: true`, подрежда по зависимости.
   Всяко изхвърляне се записва с причина.
2. **backup** — `git tag installer-backup-<stamp>` (или ZIP извън git) и
   манифест; архивът се проверява по SHA-256 **преди** първата промяна.
3. **apply** — прилага операциите върху работното дърво и спира на първия
   провал. `master` не се пипа: при нужда се създава клон `installer/<версия>`.
4. **tests** — пуска всички пакети от `installer.config.json`. Липсващ
   инструмент става *измерен пропуск с причина*, никога „тихо мина“.
5. **publish** — комит `миграция: N файла, +X/-Y реда (<версия>)`, annotated
   таг `installer-v<версия>`, release notes и `.installer/publish.json`.
   Кратката статистика за промяната се записва и като събитие `diff` в
   `.installer/journal.jsonl`, за да може всеки пуск да се проследи назад до
   точния размер на промяната. Когато миграцията не пипа файлове, редът е
   `миграция без промени във файловете`.

## Повторен пуск без промени

Втори пуск върху вече мигрирано дърво не е грешка и не публикува нищо. Ако
нито една задача не пише файл (всички вече са приложени с идентичен
fingerprint, или избраните задачи са само пазачи), инсталаторът:

* записва събитие `noop` в журнала,
* оставя фазата на състоянието `noop` (не `done`),
* не пуска тестовете и не прави комит, таг или release notes,
* излиза с код `0` и реда „Задачите са проверени, но нищо не е променено —
  без тестове и без публикуване.“

`--force` вдига само проверката „вече е завършил успешно“. Той **не** кара
вече приложена задача да се изпълни отново: пропускането на приложените
задачи остава в сила, защото повторното им прилагане би било същото писание.
За да се приложи нещо наново, декларацията трябва да се промени (нов
fingerprint) — или да се изчисти състоянието с `reset --force`.

## Проверка преди публикуване

`installer/scripts/verify.ps1` пуска същите четири проверки, които вървят и в
CI, в същия ред и от същата папка:

1. `compileall` върху `pasevsu_installer`,
2. `unittest discover` върху `installer/tests`,
3. `ruff check installer`,
4. `mypy installer/pasevsu_installer` (стриктният `installer/pyproject.toml`).

Флагът `-SkipLint` пуска само компилацията и тестовете. Скриптът връща
ненулев код при първия провал, така че е подходящ за ръчна проверка преди
`install` без `--dry-run`.

## Операции, които агентът може да прилага

Променящи (само в `changes`): `write_file_if_absent`, `write_file`
(изисква `allow_overwrite: true`), `append_block_if_absent`, `replace_once`,
`emit_selection_manifest`, `copy_asset`, `bump_version`.

Само за четене (само в `verify`): `assert_file_exists`, `assert_file_contains`,
`assert_block_present`, `assert_version`.

`bump_version` записва една обявена версия навсякъде, където тя се декларира
(`installer/VERSION`, `installer/pyproject.toml`,
`installer/pasevsu_installer/__init__.py`), и не пипа файловете, които вече са на
тази версия. Отчетената от него версия става версията на изданието — комитът,
тагът и бележките се правят с нея.

Пътищата извън корена на хранилището се отхвърлят.

## Тестови пакети

Пакетите се обявяват в `installer/installer.config.json` (`test_suites`).
Пакет с `required: true` е задължителен: негов провал спира публикуването.
Пакет с `required: false` е **съветващ** — пуска се, отчита се в отчета, но не
блокира изданието; така `langchain-v1-unit` може да е червен, без това да
скрива реална миграция. Липсващ инструмент се отчита като пропуск с причина,
никога като успех — „съветващ“ означава *провален*, а не *пропуснат*.

## Декларация на агент

```json
{
  "schema": "pasevsu.installer.agent.v1",
  "id": "installer-docs",
  "status": "active",
  "tasks": [
    {
      "id": "doc-workflow-guide",
      "declared": true,
      "changes": [{ "op": "write_file_if_absent", "params": { "path": "…", "content": "…" } }],
      "verify": [{ "op": "assert_file_exists", "params": { "path": "…" } }]
    }
  ]
}
```

Задача без `declared: true` не се изпълнява — причината се записва като
„няма ясно заявена промяна“. Задача с `declared: true`, но без нито една
операция (нито в `changes`, нито в `verify`) също се изключва.

Задача само с `verify` (без `changes`) е разрешена: тя е **пазач** — не пипа
нищо, пуска се при всяко изпълнение и провалена проверка спира публикуването.
Такава задача никога не се отчита като „вече приложена“, защото не записва
нищо.

## Артефакти от последното изпълнение

| Файл | Съдържание |
| --- | --- |
| `.installer/state.json` | фаза, брой пускания, състояние на задачите, бекъп, публикация |
| `.installer/journal.jsonl` | append-only журнал на събитията |
| `.installer/report.md` | човешки отчет: избрани, приложени, изключени, тестове |
| `.installer/selection.json` | машинен запис на селекцията |
| `.installer/backup.json` | манифест на бекъпа с SHA-256 |
| `.installer/publish.json` | комит, таг и разклонение |

`.installer/` е в `.gitignore` и никога не се комитва.

## Генерирани файлове в репото

Някои файлове в хранилището не се пишат на ръка, а се създават от задачи с
`write_file_if_absent` или `copy_asset`:

| Път | Кой го създава |
| --- | --- |
| `installer/gui/*` (`index.html`, `app.js`, `style.css`) | `installer-gui.json` чрез `copy_asset` от `pasevsu_installer/assets/gui/` |
| `AGENTS.md` | `installer-bootstrap.json` |
| `.github/workflows/installer-agent.yml` | `installer-bootstrap.json` |
| `installer/PROPOSALS.md` | `task-smith.json` (регистър на предложенията) |

Затова не трийте `installer/pasevsu_installer/assets/gui/` — това е източникът
на копието, и не трийте `installer/gui/`, докато декларацията на
`installer-gui` съществува: следващият пуск ще ги върне. `PROPOSALS.md` се
създава само при първия пуск — това е регистър на предложенията с
`declared: false`, който не променя нищо сам по себе си.

## Структура на пакета

```
installer/
├── installer.config.json     конфигурация (тестови пакети, публикуване)
├── VERSION                   текуща версия
├── agents/                   декларации на агентите
├── scripts/verify.ps1        еднокомандна проверка преди публикуване
├── pasevsu_installer/        кодът (stdlib only)
├── tests/                    unittest тестове
└── RELEASE-NOTES/            бележки по версии (пишат се при публикуване)
```
