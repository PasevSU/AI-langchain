# Installer workflow

This page describes what `pasevsu-installer-agent` actually does on first start.
It is generated by the installer itself, so it always matches the shipped code.

## Phases

| Phase | Gate | Artefact |
| --- | --- | --- |
| `selection` | only agents with a declared change task run | `.installer/selection.json`, `.installer/selected-agents.json` |
| `backup` | archive/tag verified (SHA-256) before any mutation | `.installer/backup.json` |
| `apply` | changes applied in dependency order, stop at first failure | `.installer/report.md` |
| `tests` | every required suite passes | `.installer/report.md` (test table) |
| `publish` | commit on `installer/<version>`, tag `installer-v<version>` | `.installer/publish.json`, `installer/RELEASE-NOTES/<version>.md` |

## Commands

```bash
python -m pasevsu_installer status          # read-only summary of the last run
python -m pasevsu_installer install --dry-run
python -m pasevsu_installer install --agents installer-bootstrap
python -m pasevsu_installer reset --force   # drop state, keep the git history
```

## Guarantees

- `master` is never committed to directly; the run creates `installer/<version>`.
- A task whose fingerprint was already applied with the same payload is skipped.
- A missing test toolchain becomes a *measured skip with a reason*, never a silent pass.
- The run is idempotent: repeating it does not duplicate blocks or rewrite identical files.

## Test gate: required vs optional

The `tests` phase distinguishes two kinds of suite, declared in `installer.config.json`.

| `required` | A failure or a skip | Effect on the run |
| --- | --- | --- |
| `true` | blocks | phase becomes `tests-failed`, nothing is published |
| `false` | advisory | reported in the table and the summary, **never blocks publishing** |

Only *required* suites decide whether the update may be published. An optional suite is
advisory by design — it proves something about the repository, not about the installer.
Today two suites are optional:

- `langchain-v1-unit` — the upstream unit tests of `langchain`. Part of them require POSIX
  (glob assertions with `/`, `prlimit`/`preexec`, `/bin/sh`), so they fail on Windows; the
  rest (`1294 passed`) is still measured and reported.
- `langchain-v1-lint` — `ruff check` on the upstream tree; the installer enforces its own
  lint separately.

Rule of thumb: mark a suite `required: true` only when a failure means *the installer is
broken*. Anything the installer merely observes stays optional, so a platform quirk cannot
block the release.

## Recovery

1. `cat .installer/report.md` — what was selected, applied, skipped and why.
2. `cat .installer/journal.jsonl` — append-only event log of the run.
3. `git tag --list 'installer-backup-*'` — the verified pre-migration snapshot.
4. Delete `.installer/lock.json` only if a run crashed while holding the lock.
